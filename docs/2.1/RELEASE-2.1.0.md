# Control Center 2.1.0

## Назначение

Релиз 2.1.0 стабилизирует существующий Minecraft Bedrock Server и переводит его в единый управляемый контур Control Center без плановой замены действующего мира.

## Что исправляется

До 2.1.0 на реальном сервере одновременно наблюдались два факта: процесс `bedrock_server` реально работал и слушал UDP 19132, но многосерверный контур Control Center не считал его управляемым автоматическим экземпляром. Из-за этого сервер мог быть доступен игрокам, однако операции запуска, перезапуска, обновления и восстановления зависели от того, удавалось ли обнаружить исторический systemd unit по PID.

2.1.0 устраняет это расхождение и вводит один канонический unit:

`src-control-minecraft-bedrock.service` в тексте ниже следует читать как `srv-control-minecraft-bedrock.service`.

Каноническое имя unit: `srv-control-minecraft-bedrock.service`.

## Поведение обновления

- Прямой поддерживаемый источник: реальный production 1.3.8 или опубликованный 2.0.0.
- При переходе с 1.3.8 сначала применяется и принимается полный опубликованный 2.0.0 baseline, после чего выполняется Minecraft-нормализация в рамках одной транзакции 2.1.0.
- При переходе с 2.0.0 повторная установка платформы не выполняется; сначала повторно проверяется принятый baseline 2.0.0.
- До смены владельца процесса создаётся отдельная safety-копия Minecraft-данных.
- Существующие `worlds`, `server.properties`, allowlist/permissions/whitelist не заменяются.
- Автоматическая нормализация запрещена, если обнаружено несколько runtime-каталогов или несколько процессов `bedrock_server`.
- Автоматический путь не использует SIGKILL.

## Канонический Minecraft-контур

После успешного apply:

- существует и включён `srv-control-minecraft-bedrock.service`;
- существует ровно один `bedrock_server`;
- процесс принадлежит каноническому unit;
- UDP-порт из `server.properties` слушается;
- `level-name` задан и каталог активного мира существует;
- исторические Control Center helper paths сохраняются для совместимости API, но проходят через новый dispatcher и один канонический service;
- конфликтующий `srv-control-minecraft-auto-update.timer` отключён;
- если исторический `minecraft-update.timer` существует, он остаётся single-server механизмом обновления и должен быть включён.

## Мир и переустановка

2.1.0 **не заменяет действующий мир в штатном сценарии**. Если реальная production acceptance покажет повреждение runtime или мира, исправление выпускается отдельным patch release 2.1.x. Runtime можно переустановить отдельно от пользовательских данных; замена мира допустима только после доказанной невозможности восстановления и успешной safety-копии.

## Rollback

2.1.0 сохраняет собственный rollback snapshot до изменения Minecraft helpers/unit. Для прямого перехода с 1.3.8 используется опубликованный rollback 2.0.0 для возврата полного платформенного состояния. Для источника 2.0.0 восстанавливаются прежние helpers, release marker и unit state. Если исходный Bedrock был полностью unmanaged и восстановить старый unit невозможно, rollback отдаёт приоритет доступности мира и может оставить сохранённый runtime запущенным через канонический unit, вместо остановленного игрового сервера.

## Политика 2.1.x

После публикации 2.1.0 его файлы не изменяются. Любая ошибка стабилизации исправляется в 2.1.1, затем при необходимости в 2.1.2 и далее.

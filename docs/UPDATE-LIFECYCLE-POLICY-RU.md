# Control Center — Политика обновлений и жизненного цикла

**Редакция 1.1 — 18.08.2026**

Этот документ определяет правила нумерации версий, выпуска обновлений и жизненного цикла production-релизов Control Center.

## 1. Область действия

Политика применяется к стабильным production-релизам. Preview, alpha, beta и release candidate не запускают отсчёт жизненного цикла, если прямо не объявлено иное.

Для major-линии **1.x.x** действует базовый цикл:

- **24 месяца полных обновлений**;
- затем **12 месяцев только обновлений безопасности**;
- после 36 месяцев — End of Life (EOL).

Отсчёт начинается с официальной даты выпуска `1.0.0`. То же правило является базовым для последующих major-линий, если для конкретной линии не объявлен более длительный срок.

## 2. Формат версии X.Y.Z

Control Center использует трёхкомпонентный номер `X.Y.Z`, но **не заявляет строгую совместимость с Semantic Versioning**.

- `X` — major-поколение продукта;
- `Y` — крупная функциональная линия/этап внутри major-поколения;
- `Z` — последовательный production-релиз внутри функциональной линии.

Последовательный релиз `X.Y.Z` может содержать исправления, UX-изменения, расширение существующих функций и новые возможности, если release notes явно описывают их. Поэтому релизы `1.0.5` и `1.0.6`, содержащие новые пользовательские возможности, являются корректными в принятой схеме Control Center.

При необходимости явно обозначить только исправляющее обновление это указывается в release notes как **fix-only/security-only release**, а не выводится автоматически только из позиции `Z`.

## 3. Major-релиз X.0.0

Изменение первого числа означает новое поколение продукта и может включать существенные архитектурные изменения, миграции и изменения совместимости.

Выпуск новой major-версии не прекращает досрочно уже объявленный жизненный цикл предыдущей major-линии.

Для Control Center Professional переход на новое major-поколение может являться отдельным платным upgrade, если индивидуальные условия лицензии прямо не предоставляют такое право.

## 4. Функциональные и последовательные релизы

В течение периода Full Updates могут выпускаться как новые функциональные линии `X.N.0`, так и последовательные релизы `X.Y.Z`.

Они могут включать:

- новые пользовательские функции и модули;
- расширение существующих возможностей;
- изменения UI/API/модели данных в пределах заявленной совместимости;
- исправления ошибок и регрессий;
- security fixes;
- улучшения производительности и совместимости.

Release notes и frozen manifest конкретного релиза являются авторитетным описанием его состава.

## 5. Fix-only и security-only релизы

Если релиз объявлен fix-only, он предназначен для исправления текущей функциональности и не должен добавлять самостоятельные пользовательские функции.

В период Security Only выпускаются только применимые обновления безопасности и технические изменения, необходимые для устранения уязвимостей. Новые пользовательские функции в этот период не входят в публичное обязательство поддержки.

Правообладатель определяет применимость уязвимости к поддерживаемой версии и возможность безопасного backport. Если отдельным договором не установлен SLA, настоящая политика не гарантирует конкретный срок выпуска исправления для каждой уязвимости.

## 6. Полный жизненный цикл major-линии

### Первые 24 месяца — Full Updates

Major-линия может получать функциональные и последовательные production-релизы, bug fixes, compatibility fixes и security updates.

### Следующие 12 месяцев — Security Only

Для major-линии выпускаются только применимые security updates. Обычные новые функции и функциональные улучшения в публичную поддержку этого периода не входят.

### После 36 месяцев — End of Life

Публичное обязательство выпускать обновления прекращается. Правообладатель может выпустить чрезвычайное исправление, но оно не возобновляет жизненный цикл.

Установленная версия может продолжать работать в пределах действующей лицензии. Окончание update entitlement или EOL само по себе не должно останавливать уже работающие инфраструктурные сервисы.

## 7. Официальные даты

Авторитетной датой начала жизненного цикла является дата официальной публикации production-релиза `X.0.0`.

Конкретные даты окончания Full Updates, перехода в Security Only и EOL публикуются в release notes/metadata соответствующей major-линии.

Даты не рассчитываются от момента покупки или активации отдельным пользователем. Индивидуальный Professional-договор может предоставлять расширенное обслуживание.

## 8. Production metadata

Текущая опубликованная версия определяется `deployment.json`. Состав конкретного релиза фиксируется его manifest и release notes.

Для точной идентификации сборки metadata может дополнительно содержать поле `build`; основным пользовательским номером релиза остаётся `X.Y.Z`.

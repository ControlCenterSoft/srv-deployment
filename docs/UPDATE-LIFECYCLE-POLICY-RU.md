# Control Center — Политика обновлений и жизненного цикла

**Редакция 1.0 — 18.08.2026**

Этот документ определяет правила версионирования, выпуска обновлений и жизненного цикла стабильных production-релизов Control Center.

## 1. Область действия

Политика применяется к стабильным production-релизам. Preview, alpha, beta и release candidate не запускают отсчёт жизненного цикла, если Правообладатель прямо не объявил иное.

Для major-линии **1.x.x** действует базовый цикл:

- **24 месяца полных обновлений**;
- затем **12 месяцев только обновлений безопасности**;
- после 36 месяцев — End of Life (EOL).

Отсчёт начинается с официальной даты выпуска `1.0.0`.

То же правило является базовым для последующих major-линий `X.x.x`, если для конкретной линии публично не объявлен более длительный срок поддержки.

## 2. Формат версии X.Y.Z

Control Center использует трёхкомпонентный номер версии `X.Y.Z`.

- `X` — major-поколение продукта;
- `Y` — функциональный minor-релиз внутри major-линии;
- `Z` — patch-релиз с исправлениями текущей функциональности.

Пример: `1.4.2` — major-линия 1, функциональный релиз 4, второе исправляющее обновление этой функциональной линии.

## 3. X.N.x — функциональный релиз

Изменение второго числа версии означает функциональный релиз. Например, `1.3.x → 1.4.0`.

Функциональный minor-релиз может включать:

- новые пользовательские функции и модули;
- расширение существующих возможностей;
- изменения UI/API/модели данных в пределах политики совместимости;
- исправления ошибок;
- обновления безопасности;
- изменения совместимости и производительности.

Номер `N` во второй позиции является номером очередного функционального релиза внутри major-линии.

## 4. X.x.N — исправляющий релиз

Изменение третьего числа версии означает patch-релиз. Например, `1.4.1 → 1.4.2`.

**Patch-релиз не должен добавлять новые пользовательские функции.** Он предназначен для исправления уже существующей функциональности и может включать:

- исправление дефектов и регрессий;
- security fixes;
- исправления стабильности и производительности;
- исправления совместимости, если они не вводят новую самостоятельную функцию;
- минимальные технические изменения, необходимые для устранения дефекта или уязвимости.

Если изменение создаёт новую пользовательскую возможность или существенно расширяет продуктовую функцию, оно должно выпускаться как `X.N.0`, а не как patch.

## 5. Полный жизненный цикл major-линии

Отсчёт начинается с официальной даты публикации стабильного релиза `X.0.0`.

### Первые 24 месяца — Full Updates

Поддерживаемая major-линия может получать:

- функциональные minor-релизы `X.N.0`;
- patch-релизы `X.x.N`;
- исправления ошибок;
- улучшения совместимости;
- обновления безопасности.

### Следующие 12 месяцев — Security Only

В течение третьего года поддержки для major-линии выпускаются только применимые обновления безопасности.

Не входят в обязательную поддержку этого периода:

- новые функции;
- обычные функциональные улучшения;
- новые функциональные minor-релизы;
- обычные исправления, не связанные с безопасностью.

Изменение поведения, технически необходимое для устранения уязвимости, считается security fix и не считается новой функцией.

Правообладатель определяет применимость уязвимости к поддерживаемой версии и техническую возможность безопасного backport. Если отдельным договором поддержки не установлен SLA, настоящая политика не гарантирует конкретный срок выпуска исправления для каждой обнаруженной уязвимости.

## 6. Новая major-версия

Изменение первого числа версии, например `1.x.x → 2.0.0`, означает новое major-поколение. Оно может включать существенные архитектурные изменения, миграции и изменения совместимости.

Выпуск новой major-версии не прекращает досрочно уже объявленный жизненный цикл предыдущей major-линии. Поддержка старой линии продолжается до её собственного EOL.

Для Control Center Professional переход на новое major-поколение может являться отдельным платным upgrade, если индивидуальные условия лицензии прямо не предоставляют такое право.

## 7. Официальные даты

Авторитетной датой начала жизненного цикла является дата официальной публикации production-релиза `X.0.0`.

Конкретные календарные даты:

- окончания Full Updates;
- перехода в Security Only;
- End of Life;

публикуются в release notes/metadata соответствующей major-линии.

Даты не рассчитываются от момента покупки или активации отдельным пользователем. Индивидуальный Professional-договор может предоставлять расширенное обслуживание сверх публичного жизненного цикла.

## 8. После End of Life

После 36 месяцев публичное обязательство выпускать обновления для major-линии прекращается.

Правообладатель может по своему усмотрению выпустить чрезвычайное исправление, но такое исправление:

- не возобновляет жизненный цикл;
- не создаёт новый обязательный период поддержки.

Установленная версия может продолжать работать после EOL в пределах действующей лицензии, однако эксплуатация версии без security-поддержки осуществляется с повышенным риском. Рекомендуется переходить на поддерживаемую major-линию.

Окончание update entitlement не отключает уже активированную установку и не должно само по себе останавливать уже работающие критические инфраструктурные сервисы.

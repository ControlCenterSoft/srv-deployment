# SRV Control Center 1.1.0 — User-requested administration rework

Этот релиз содержит только изменения, перечисленные владельцем проекта. Дополнительные функции из общего roadmap в 1.1.0 не включаются. После завершения и acceptance 1.1.0 разработка возвращается к ранее согласованному плану.

## Обязательный состав 1.1.0

1. Вынести управление учётными записями, авторизацией, группами пользователей и назначением прав на управление модулями в отдельный пункт меню **«Права пользователей»**.
2. Не создавать собственные пользовательские учётные записи SRV Control Center. Использовать локальные учётные записи Linux-сервера; если домен поднят и настроен — использовать доменные учётные записи. Пользователь root и пользователи, имеющие административные root/sudo-права на сервере, получают полный доступ ко всем модулям Control Center.
3. Реализовать групповые роли для модулей **«Домен / Samba»**, **«PXE сервер»**, **«Minecraft»**, **«Docker»**, **«Сеть»**, **«Загрузки»**. Для каждой роли доступны уровни **«Чтение»** и **«Запись»**. Назначение выполняется группам пользователей; для доменной среды — доменным группам. После переименования UI-пункта «Загрузки» в «Торренты» внутренний идентификатор модуля может оставаться совместимым с `downloads`, но пользовательское название и отображение роли должны быть «Торренты».
4. Любой просмотр Control Center требует авторизации. Поддерживаются локальные учётные записи сервера и доменные учётные записи. Для доменного компьютера должен поддерживаться SSO доменной учётной записи через Kerberos/SPNEGO с безопасным fallback на интерактивную авторизацию, если SSO недоступен.
5. В **«Система»** добавить настройки обновлений Control Center из GitHub: источник, режим обновления **ручной / по расписанию**, период проверки при автоматическом режиме, кнопка **«Проверить обновления»** в ручном режиме и кнопка **«Обновить»**, активная только при наличии доступного нового product-релиза.
6. Переименовать меню **«Загрузки»** в **«Торренты»**.
7. Настройки **AdGuard VPN** вынести в отдельный пункт главного меню.
8. Уменьшить кнопку перезагрузки сервера и разместить её в заголовке страницы **«Система»** рядом со статусом **«Данные актуальны»**.
9. **Обновление ОС и пакетов**: переключатель режима **ручной / автоматический**. В автоматическом режиме активируется выбор периода в часах от 1 до 24. В ручном режиме активируется кнопка **«Обновить сервер»**.
10. В **«Система»** добавить управление резервным копированием: включение/выключение резервного копирования по расписанию и настройка расписания; отдельный переключатель **«Резервное копирование при обновлении»**; список резервных копий с датой, релизом, размером и пользователем, создавшим копию; создание, удаление, скачивание и восстановление. Резервная копия должна включать базу Control Center, его state/config и копии системных параметров/файлов, которые Control Center изменяет на сервере.
11. Добавить отдельный пункт меню **«Сервисы»**. В 1.1.0 каталог содержит **AdGuard VPN** и **PXE Server**, с реальным определением установлен/не установлен и доступными действиями установки/удаления согласно правам пользователя.
12. Не выводить в UI временные уведомления и заглушки вида «пока не работает», «будет реализовано позже», «недоступно потому что...». Интерфейс показывает только реально реализованные состояния и доступные действия. Функции, не готовые к acceptance, не должны отображаться как пользовательские элементы.

## Архитектурные правила

- `main` остаётся production-каналом; разработка выполняется только в `release/1.1.0-user-requested-admin-rework` до полного preflight + acceptance.
- `server-state` остаётся каналом фактического состояния SRV.
- Никакой собственной таблицы пользователей/паролей Control Center для входа. Авторизация опирается на системный PAM/NSS и, при наличии домена, Kerberos/Winbind/SSSD/Samba-интеграцию сервера.
- Пароли локальных/доменных пользователей не сохраняются в БД Control Center, логах, audit или state-файлах.
- RBAC хранит только сопоставление групп с модульными правами Read/Write и служебную конфигурацию авторизации.
- `root`/UID 0 и подтверждённые серверные администраторы получают полный доступ без необходимости вручную назначать каждую модульную роль.
- Все операции Write требуют авторизованной сессии, CSRF-защиты и audit-события.
- SSO не должен превращаться в обход проверки прав: Kerberos-аутентификация определяет identity, после чего применяется тот же RBAC.
- GitHub updater должен различать проверку наличия обновления и фактическое применение; ручная проверка не изменяет систему.
- Резервное копирование перед обновлением выполняется до `apply`; ошибка backup при включённой политике блокирует update.
- Восстановление резервной копии является отдельной привилегированной операцией с preflight, проверкой архива и audit.
- Удаление/установка сервисов выполняется только через ограниченный root-owned helper/agent, а не непосредственно web-процессом.

## Acceptance 1.1.0

Релиз считается готовым только если одновременно выполнено следующее:

- без авторизации `/`, все UI-модули и защищённые API не раскрывают содержимое Control Center;
- локальная Linux-учётная запись может войти с собственным системным паролем, не создавая отдельной УЗ Control Center;
- при доступной доменной конфигурации доменная учётная запись определяется и проходит RBAC; SPNEGO/SSO проверяется отдельно;
- root/server-admin имеет полный доступ;
- группа с Read видит модуль и read-only API, но получает отказ на write-операции;
- группа с Write получает разрешённые операции соответствующего модуля;
- GitHub check/update, OS update mode/period, backups и service catalog реально работают и сохраняют настройки;
- backup можно создать, скачать, удалить и восстановить; метаданные содержат дату, релиз, размер и actor;
- AdGuard VPN и PXE Server отображаются в «Сервисы» с фактическим состоянием;
- «Торренты», «Права пользователей», «AdGuard VPN» и «Сервисы» находятся в главном меню;
- кнопка reboot находится рядом с «Данные актуальны» и требует write/admin права;
- в интерфейсе отсутствуют временные placeholder-сообщения;
- после deployment проходят healthcheck, DB migration, auth/RBAC tests, backup/restore smoke test и updater smoke test;
- rollback возвращает предыдущую рабочую версию без потери доступа к серверу.

## Не включать в 1.1.0

Никакие дополнительные функции общего roadmap, новые сервисы сверх AdGuard VPN и PXE Server, новые сетевые apply-функции, Minecraft/PXE feature expansion или другие продуктовые улучшения не добавляются, если они не нужны непосредственно для выполнения пунктов выше.

# Control Center 1.0.0-rc.1 — Production Candidate

Status: implementation candidate
Base: accepted `1.0.0-beta.1` commit `b3b7cd7d3a1985bbe02b392bce5e26d5bf0cf39c`

## Objective

Freeze the implemented 1.0.0 product contracts and prove production readiness. rc.1 adds no new end-user scope. Any code change after this point must be a narrowly scoped acceptance/security/reliability fix with regression evidence.

## Frozen product contracts

- Web navigation: Обзор / Маркет / RBAC / Система.
- Local authentication and server-side admin/viewer RBAC.
- State schema `1` and operations schema `1`.
- CSRF/origin enforcement, auth rate limiting, secure session-cookie default and security headers.
- Non-root runtime and systemd hardening.
- Operations, correlated audit and whitelist-only diagnostics export.
- Immutable release directories with atomic `current`/`previous` activation.
- Ed25519 signed manifest schema `1`, artifact SHA-256/size binding and platform/state-schema verification.
- Same-version/downgrade rejection by default.
- Automatic rollback and immediate known-good restart without stale systemd start-rate blocking.
- Install / repair / reinstall / non-purge uninstall-reinstall lifecycle with state and update-trust preservation.

## Reproducible release-build contract

rc.1 freezes its release toolchain as part of artifact identity:
- module language baseline: Go `1.23.0`;
- exact release compiler: Go `1.23.2`;
- `GOTOOLCHAIN=local` for release builds, so the toolchain cannot silently change;
- exact source commit is the full Git `HEAD` SHA;
- `built_at` is the immutable committer timestamp of that source commit;
- builds use `-trimpath -buildvcs=false` and `CGO_ENABLED=0`;
- linux/amd64 and linux/arm64 are rebuilt from the same source/toolchain/metadata;
- `scripts/build-release.sh` requires a clean Git tree and emits `dist/BUILDINFO.env` plus `SHA256SUMS`.

The same source commit built twice through the exact-release path must produce byte-identical checksums. A compiler/toolchain mismatch is a release blocker rather than an allowed artifact variation.

## rc.1 implementation adaptation

The rc.1 changes are release/acceptance-only:
- CI and exact release builds use the pinned Go `1.23.2` toolchain;
- exact release candidate version is `1.0.0-rc.1` and is bound to its full source commit;
- signed forward-update acceptance uses synthetic `1.0.0-rc.2`;
- broken signed-candidate acceptance uses synthetic `1.0.0-rc.3`;
- post-rollback acceptance explicitly restarts the restored known-good runtime and rejects residual failed/start-limit state;
- clean-install CI asserts the secure loopback listen default;
- CI restores exact rc.1 after synthetic update tests before lifecycle acceptance;
- deterministic source secret scanning is a mandatory gate.

No API, state schema or privilege contract changes are introduced by this adaptation.

## Mandatory production-candidate gates

rc.1 cannot be accepted until all release gates are evidenced for one exact source commit, including:
- formatting, unit/API tests, vet and script/Web syntax;
- pinned-toolchain reproducible amd64 and arm64 static builds with exact build-info and SHA-256;
- secret scan and signed-package verification;
- clean install on a disposable supported systemd host;
- upgrade from the accepted beta.1 real-host state;
- Auth/RBAC, CSRF/origin, rate-limit, Operations/Audit/Diagnostics regression;
- controlled restart and OS reboot recovery;
- signed forward update, broken-candidate rollback and immediate post-rollback restart;
- repair/reinstall and preserve-state uninstall/reinstall;
- explicit purge isolation on a disposable host;
- secure product default (loopback runtime + Secure cookies);
- read-only CI evidence with no workflow self-write to `main`;
- zero blocker/critical release defects.

## Source identity rule

A release candidate is invalid if source commit, compiler/toolchain, embedded build-info, signed manifest, checksums or acceptance evidence refer to different identities. Closure/evidence updates after candidate freeze belong on evidence branches rather than mutating the accepted candidate source identity.

## Deferred

Domain/AD, DHCP/DNS, shares, Minecraft, advanced Market/module lifecycle, remote automatic update discovery/download, Web-triggered privileged self-update, production HSM/signing-key lifecycle, licensing/support agent and Android clients remain outside Platform 1.0.0 rc.1 scope.

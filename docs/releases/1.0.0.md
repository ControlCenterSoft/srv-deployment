# Control Center 1.0.0

Status: stable production candidate

## Baseline

Stable 1.0.0 is promoted from the accepted `1.0.0-rc.1` code line at commit `77b62d5829a46b1b29698495043146d79f37dc48`. No new end-user functionality is introduced by the stable promotion.

## Frozen contracts

The following contracts remain unchanged from accepted rc.1:
- runtime API surface
- state schema 1
- operations schema 1
- Auth/RBAC semantics
- operations/audit/diagnostics model
- signed Ed25519 update manifest and trusted verification
- immutable release directories and atomic `current`/`previous` symlinks
- automatic rollback and immediate known-good restart recovery
- secure loopback product default

## Stable release identity

- version: `1.0.0`
- Go toolchain: `1.23.2`
- build timestamp: Git commit epoch canonicalized to UTC RFC3339 `...Z`
- architectures: linux/amd64 and linux/arm64
- exact builder: `./scripts/build-release.sh`
- metadata: `release/1.0.0.env`

## Stable update acceptance

`./scripts/stable-update-acceptance.sh` validates:
- signed forward update `1.0.0 -> 1.0.1`
- same-version rejection
- artifact tamper rejection before execution
- strict package whitelist
- wrong-architecture rejection
- signed downgrade rejection to `1.0.0-rc.1`
- signed metadata tamper rejection
- correctly signed non-starting `1.0.2`
- automatic rollback to known-good `1.0.1`
- immediate restart after rollback without `start-limit-hit`

The test uses a private hermetic Go cache so it remains valid in non-interactive/systemd environments.

## Production gates

Stable release is not accepted until one exact candidate passes:
- source/static/unit/vet/syntax/secret validation
- reproducible exact amd64/arm64 build
- exact artifact SHA evidence
- signed package verification and negative tamper checks
- clean install
- accepted rc.1 -> exact 1.0.0 signed upgrade
- browser/Auth/RBAC/security regression
- real reboot/autostart/readiness
- signed forward update and broken-candidate rollback
- repair/reinstall
- preserve-state uninstall/reinstall
- diagnostics export
- remote CI on the exact frozen stable SHA
- zero blocker/critical release debt

## Governance

Stable implementation remains isolated from `main`. No PR or merge to `main` is authorized by this document. Current `main` divergence must be resolved explicitly before production integration.

# Control Center 1.0.0

Status: implementation candidate

## Release objective

Promote the accepted `1.0.0-rc.1` runtime to the first stable `1.0.0` release without adding new end-user functionality.

Accepted RC baseline:
- version: `1.0.0-rc.1`
- commit: `77b62d5829a46b1b29698495043146d79f37dc48`
- state schema: `1`
- operations schema: `1`
- Go toolchain: `1.23.2`

## Scope freeze

Stable 1.0.0 preserves the accepted RC contracts for:
- local authentication and server-side sessions;
- RBAC and protected API routing;
- persistent state and schema 1;
- operations, audit and diagnostics;
- systemd service lifecycle;
- immutable releases and atomic `current` / `previous` links;
- Ed25519 signed release manifests;
- SHA-256 artifact integrity and exact package whitelist;
- fail-closed update verification and automatic rollback;
- repair, reinstall, preserve-state uninstall and purge.

No new user-facing module or navigation item is introduced in this release.

## Production release hardening

The stable branch additionally requires:
- exact release identity `1.0.0`;
- pinned Go `1.23.2` with `GOTOOLCHAIN=local`;
- commit-derived UTC `built_at`;
- byte-for-byte reproducible amd64 and arm64 builds;
- official CI assertions that respect protected `0750` Control Center directories;
- stable update regression using signed `1.0.1` and broken signed `1.0.2` candidates;
- exact `rc.1 -> 1.0.0` real-host upgrade and reboot evidence;
- final stable closure evidence kept outside the frozen product candidate.

## Explicit non-scope

- Domain Services / AD provisioning;
- DNS/DHCP/IPAM implementation;
- new Market capabilities;
- remote unattended Internet update download;
- privileged self-update initiated directly by the Web process;
- HTTPS/public certificate rollout (current acceptance ingress remains the explicitly temporary HTTP test ingress);
- `main` integration.

## Release identity rule

Once a stable candidate has passed exact local validation, its source SHA is frozen. Evidence-only changes must be recorded on separate evidence branches and must not redefine the candidate binary identity.

## Main integration rule

Acceptance of 1.0.0 does not authorize a PR or merge to `main`. The existing `main` divergence and CI-governance history must be resolved explicitly before any integration action.

## Real-host defect discovered by acceptance

After the intentionally broken beta.3 candidate, systemd accumulated start-rate failure state. A subsequent controlled repair could fail with `start-limit-hit` even though `current` already pointed to the known-good beta.1 runtime.

Diagnostic recovery proved:
- `RECOVERY_REASON=start-limit-hit`;
- exact beta.1 version/commit remained installed;
- `systemctl reset-failed control-center.service` followed by controlled start restored readiness;
- users/state were not lost;
- temporary browser ingress became healthy again.

## Product fix

Commit `75ac950eefbc1b70b77bc93373444011791c4415` adds narrowly scoped recovery behavior:
- installer clears only the Control Center unit failure/start-rate state before a controlled verified-runtime restart;
- updater clears the same state before controlled target start;
- updater clears it again before starting the known-good target during rollback.

The final evidence candidate `b3b7cd7d3a1985bbe02b392bce5e26d5bf0cf39c` contains this product fix plus synchronized validation/release documentation.

# Control Center 1.0.0 production acceptance matrix

Every gate below is blocking unless explicitly marked informational.

| ID | Gate | Required evidence |
|---|---|---|
| ST-01 | Exact source identity | Frozen full Git commit SHA recorded. |
| ST-02 | Toolchain identity | `go env GOVERSION == go1.23.2`; `GOTOOLCHAIN=local`. |
| ST-03 | Formatting | `gofmt -l .` empty. |
| ST-04 | Vet | `go vet ./...` passes. |
| ST-05 | Unit/API tests | `go test ./...` passes. |
| ST-06 | Shell/JS syntax | Installer/updater/acceptance shell syntax and Web JS syntax pass. |
| ST-07 | Secret scan | No private-key material, secret-bearing source files or live-token prefixes. |
| ST-08 | Exact amd64 build | Static linux/amd64 artifact built from frozen SHA. |
| ST-09 | Exact arm64 build | Static linux/arm64 artifact built from frozen SHA. |
| ST-10 | Build metadata | Version `1.0.0`, full commit and canonical UTC commit timestamp. |
| ST-11 | Reproducibility | Two independent exact builds produce identical `BUILDINFO.env` and SHA-256 values. |
| ST-12 | Package whitelist | Signed package contains only `control-center`, `manifest.json`, `manifest.sig`. |
| ST-13 | Signature verification | Valid Ed25519 package verifies. |
| ST-14 | Manifest tamper | Signed metadata modification is rejected. |
| ST-15 | Artifact tamper | Candidate byte modification is rejected before execution. |
| ST-16 | Wrong architecture | Signed package for wrong architecture is rejected. |
| ST-17 | Same-version protection | Reapplying same version is rejected without state/link change. |
| ST-18 | Downgrade protection | `1.0.0-rc.1` package is rejected from stable unless explicit controlled downgrade is used. |
| ST-19 | Clean install | Supported clean Ubuntu 24.04 host reaches active/ready state. |
| ST-20 | Secure filesystem | Config/state/log directories remain `0750`; protected assertions require appropriate privilege. |
| ST-21 | Secure listen default | Backend binds loopback by default. |
| ST-22 | Authentication/RBAC | Login/session/CSRF/origin/RBAC regression passes. |
| ST-23 | Operations/Audit/Diagnostics | Protected endpoints and diagnostics export pass. |
| ST-24 | RC -> stable upgrade | Exact accepted `1.0.0-rc.1` upgrades to exact `1.0.0`. |
| ST-25 | State preservation | `state.json` and `secrets.json` hashes survive upgrade unchanged. |
| ST-26 | Real reboot | Stable survives real host reboot, autostarts and returns ready with exact identity. |
| ST-27 | Stable forward update | Signed synthetic `1.0.1` is accepted and becomes healthy. |
| ST-28 | Broken stable rollback | Correctly signed non-starting `1.0.2` rolls back automatically. |
| ST-29 | Start-limit regression | Known-good runtime immediately restarts after rollback without manual `reset-failed`. |
| ST-30 | Exact stable restore | Synthetic tests restore exact frozen `1.0.0`. |
| ST-31 | Repair/reinstall | `--repair` and `--reinstall` preserve readiness and exact release identity. |
| ST-32 | Preserve-state uninstall/reinstall | Non-purge uninstall preserves config/trust/state and reinstall restores service. |
| ST-33 | Purge uninstall | Purge removes config/state/log/runtime/updater and leaves service inactive. |
| ST-34 | Update trust hygiene | Original trust restored after acceptance; ephemeral private key removed. |
| ST-35 | GitHub CI | Official or detached CI validates the exact frozen SHA with source/build/systemd jobs green. |
| ST-36 | CI governance | CI uses read-only contents access; no CI commit/push to `main`. |
| ST-37 | Diagnostics evidence | Sanitized report records exact SHA/hashes/gates and contains no credentials/session material/private key. |
| ST-38 | Zero blocker debt | No unresolved blocker/critical defect remains. |
| ST-39 | Closure record | Final accepted evidence is recorded outside the frozen product branch. |
| ST-40 | Main isolation | No PR/merge to `main` without explicit authorization and divergence review. |

Production status may be set to ACCEPTED only after ST-01 through ST-40 pass.

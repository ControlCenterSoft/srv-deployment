# Control Center 1.1.x — signed manifest v2 progress

Статус: development evidence / documentation sync

## Baseline

Production baseline остаётся неизменным: Control Center 1.0.0, accepted source commit `1b364ae88789696bf98537d21544de8a259d086d`. Этот документ не меняет frozen/accepted runtime identity и не является promotion в `main`.

## Реализовано в 1.1.x

На integration branch `1.1.x` реализован подписанный update manifest schema v2 для dual-runtime update. Текущий development head на момент фиксации: `d71a217c258db62e6acf91962d56f653ce8fa290`.

Срез включает:

- versioned manifest v2 contract;
- криптографическую привязку основного Control Center runtime и privileged-worker artifact;
- fail-closed проверку неизвестных полей и несовместимой структуры;
- security-negative regression tests для tampered privileged-worker hash и malformed/unknown-field inputs;
- сохранение независимой accepted identity 1.0.0: schema v2 относится только к development-линии 1.1.x и не переопределяет manifest schema 1 принятого stable runtime.

## Governance

Manifest v2 не считается production contract до прохождения full candidate gate 1.1.x: exact candidate SHA, reproducible artifacts, disposable install, signed update/rollback, Auth/Operations/repair acceptance и обязательного real staging evidence.

`main` и canonical stable metadata должны оставаться на 1.0.0 до отдельного явного promotion-разрешения после green acceptance.

## Следующие gate

1. Связать manifest v2 с полным package/update path dual-runtime bundle.
2. Подтвердить atomic activation и rollback обоих runtime artifacts как единой release identity.
3. Проверить repair/reinstall preservation и отказоустойчивость при частично повреждённом worker artifact.
4. Выполнить real-host staging acceptance с pinned transport и staging signing key.
5. После evidence обновить ADR-0006 отдельным совместимым transition section; существующий accepted schema 1 contract не переписывать задним числом.

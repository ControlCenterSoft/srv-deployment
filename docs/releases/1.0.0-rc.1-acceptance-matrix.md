# Control Center 1.0.0-rc.1 — Acceptance Matrix

Status: planning only. Implementation and execution are blocked until beta.1 final real-host resume acceptance passes.

## Entry condition

The rc.1 implementation branch may be created only after the accepted beta.1 source/evidence head is frozen and the real-host resume gate proves that the systemd start-limit regression is closed.

## Candidate identity

Every rc.1 artifact must bind the same immutable source identity:
- semantic version `1.0.0-rc.1`;
- exact Git commit SHA;
- linux architecture (`amd64` or `arm64`);
- artifact SHA-256 and exact byte size;
- signed manifest schema `1`;
- state schema compatibility `1..1` unless an accepted ADR changes it.

A candidate is invalid if source docs, embedded build-info, release manifest or acceptance evidence refer to different commits.

## Real-host sequencing

The production-candidate host test must run in this order so failures are attributable and rollback evidence is preserved:

1. Record pre-upgrade beta.1 identity, state revision, user count, trust-key fingerprint and service status.
2. Install/upgrade exact rc.1 candidate.
3. Verify health/readiness/version, directory modes and service hardening.
4. Execute browser-path Auth/RBAC and security gates.
5. Execute Operations/Audit/Diagnostics regression.
6. Restart service and verify immediate readiness.
7. Reboot the host and verify enabled service plus readiness.
8. Exercise signed synthetic forward update.
9. Exercise signed intentionally broken candidate and automatic rollback.
10. Immediately restart restored known-good runtime and explicitly check that systemd start-rate state is not blocking it.
11. Restore exact rc.1 candidate.
12. Execute repair and reinstall.
13. Execute non-purge uninstall/reinstall and verify state/update-trust preservation.
14. Generate final secret-safe diagnostics/evidence bundle.

## Evidence rules

- Reports must never include passwords, password hashes, session cookies, CSRF tokens, request bodies containing credentials, or private signing keys.
- Test private keys are ephemeral and must be removed even when acceptance fails.
- Evidence must include the exact product commit and installed `current` target.
- A successful local test does not substitute for real systemd-host acceptance.
- An absent GitHub status/check is `unknown`, never `passed`.
- A test-only HTTP ingress is not evidence that the secure product default permits plaintext remote access.

## Promotion decision

`1.0.0-rc.1` may be called an accepted release candidate only when RC-01 through RC-34 are either PASS or explicitly marked N/A by an accepted ADR/release decision. Any blocker gate failure returns the lifecycle to implementation/fix and requires rerunning the affected gate plus all downstream gates whose assumptions may have changed.

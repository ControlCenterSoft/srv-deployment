# Control Center 1.0.0 Stable Release Plan

Status: planning only

Baseline:
- accepted release candidate: 1.0.0-rc.1
- frozen source commit: 77b62d5829a46b1b29698495043146d79f37dc48
- accepted amd64 SHA-256: dd1bae6364657c1f65a72c63e428f61df58d0030ee85b5320ede6a598a6a6c1d
- accepted arm64 SHA-256: fadd38f5211442073a071a3d87cad35bc1f4f89c0e3466a36861f40dbbf8f54e
- accepted Go toolchain: 1.23.2
- real-host acceptance: passed
- remote detached CI: passed (run 32386851641, context control-center/rc1-detached-ci)

Goal:
Promote the accepted rc.1 code line to 1.0.0 stable without adding end-user features or changing runtime API/state/security semantics.

Allowed stable implementation changes:
- release identity 1.0.0
- stable release metadata and changelog
- deterministic build/packaging metadata required for 1.0.0
- CI/evidence wiring that does not change runtime behavior
- blocker fixes discovered by stable acceptance; any blocker fix creates a new candidate identity and requires regression review

Explicit non-scope:
- new product features
- state schema changes
- operations schema changes
- Auth/RBAC behavior changes
- networking/domain/DNS/Market feature expansion
- privileged architecture changes
- automatic main integration

Stable gates:
1. exact source identity frozen from accepted rc.1 baseline
2. Go 1.23.2 pinned and GOTOOLCHAIN=local
3. canonical UTC commit-derived built_at
4. gofmt, go vet, go test ./...
5. shell and JavaScript syntax validation
6. secret scan
7. reproducible amd64/arm64 build with byte-for-byte rebuild equality
8. exact 1.0.0 build-info and artifact SHA evidence
9. Ed25519 signed package verification and tamper rejection
10. clean install on supported Ubuntu 24.04 host
11. accepted rc.1 -> exact 1.0.0 signed upgrade
12. browser/Auth/RBAC/CSRF/origin regression
13. real reboot/autostart/readiness on exact stable candidate
14. post-reboot protected API regression
15. forward signed update to synthetic 1.0.1 and broken 1.0.2 automatic rollback
16. immediate known-good restart after rollback without start-limit-hit
17. restore exact 1.0.0 candidate
18. repair/reinstall
19. non-purge uninstall/reinstall preserving state, secrets and update trust
20. purge uninstall on disposable CI runner
21. diagnostics export and secret-free evidence
22. remote CI status on exact frozen stable SHA
23. zero blocker/critical release debt
24. explicit production release decision

Governance:
- stable work is isolated from main
- no PR or merge to main without explicit authorization
- current main divergence must be resolved before eventual integration
- release evidence must not self-modify main
- product candidate and closure evidence must remain separate identities

Production decision rule:
1.0.0 may be declared production-ready only after all stable gates are PASSED on one exact immutable candidate. Documentation-only closure evidence after acceptance does not redefine the accepted runtime source identity.

# Control Center 1.0.0-alpha.3 — Operations, Audit & Diagnostics Foundation

Status: implementation candidate

## Scope
- Persistent operation store with schema 1.
- Explicit `running`, `succeeded`, `failed` and `interrupted` operation states.
- Automatic interruption evidence for operations left running across process restart.
- Dedicated append-only JSONL audit log correlated by operation ID.
- Extended authenticated system/runtime status.
- Admin operation history and audit history APIs.
- Safe diagnostics summary available to authenticated viewers.
- Admin-only diagnostics tar.gz export built from a strict whitelist.
- Diagnostic bundle manifest/version/runtime/users/audit/operations records with no secret material.
- Web System page operational summary and diagnostics export action.
- Installed-runtime operations/diagnostics acceptance integrated into CI.

## Out of scope
Arbitrary systemd/service control, privileged system changes, raw journal export, host filesystem collection, module installation, Domain/AD, DHCP/DNS, storage management and update/rollback implementation remain out of scope.

## Acceptance gates
1. `gofmt`, `go vet`, unit/API tests and shell syntax pass.
2. linux/amd64 and linux/arm64 static binaries build with verified SHA-256 checksums.
3. Running operations persist and become `interrupted` after process restart.
4. Admin can read operation/audit evidence and export diagnostics.
5. Viewer can read safe system/diagnostic summaries but cannot read audit/operations or export diagnostics.
6. Diagnostic archive contains only approved entries and does not expose password hashes, bootstrap credentials, session tokens or request bodies.
7. Process-level bootstrap -> readiness -> Auth/RBAC -> operations/diagnostics smoke passes.
8. Clean systemd install -> restart -> Auth/RBAC -> operations/diagnostics -> repair/reinstall -> preserve-state reinstall -> explicit purge passes in recorded external evidence.

Promotion remains subject to recorded systemd/CI or equivalent real-host acceptance. This candidate does not retroactively mark earlier release gates as accepted without evidence.

# Control Center 1.1.x — план линии разработки

Статус: development

## Baseline

- production baseline: 1.0.0;
- accepted source commit: `1b364ae88789696bf98537d21544de8a259d086d`;
- development integration branch: `1.1.x`;
- first development identity: `1.1.0-dev.1`.

## Цель линии

Расширить системное управление и эксплуатационные функции без breaking changes платформенных контрактов 1.0.

Первый архитектурный вертикальный срез — узкий allowlisted privileged worker по ADR-0005. Он не предоставляет произвольный shell и должен иметь permission-negative, malformed-input, timeout, audit-correlation и recovery tests.

## Development gate

Параллельно выполняются:

- Go format/vet и shell syntax;
- secret scan;
- unit/contract tests;
- Gemini reviewer regression;
- linux/amd64 build;
- linux/arm64 build;
- проверка воспроизводимости принятого stable 1.0.0.

Любой mandatory failure блокирует интеграцию.

## Acceptance gate

Acceptance запускается только для exact candidate SHA.

Удалённый staging не разрешается до появления versioned typed `scripts/staging-deploy.sh`. Такой entrypoint обязан выполнять только определённые операции staging lifecycle и не принимать произвольную shell-команду.

После появления staging-контракта acceptance расширяется до:

candidate → deploy staging → readiness → auth/RBAC regression → operations/diagnostics → security/negative → restart/reboot → repair/update/rollback → evidence.

## Правило готовности

UI или код сами по себе не означают готовность. Для функции нужны применимые contract, permission/security model, implementation, tests, negative tests, diagnostics/observability, failure/repair behavior, документация и acceptance evidence.

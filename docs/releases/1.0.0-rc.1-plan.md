# Control Center 1.0.0-rc.1 — Production Candidate Plan

Status: planning only; implementation is blocked until beta.1 real-host acceptance is closed.

## Objective
Produce the first production-candidate build without adding new product scope. rc.1 freezes the 1.0.0 contracts already implemented through beta.1 and focuses on release reproducibility, production acceptance, failure recovery and evidence completeness.

## Entry gate
rc.1 implementation may begin only after beta.1 final resume acceptance passes for the preserved real-host state, including:
- start-limit regression after intentionally broken signed candidate;
- exact beta.1 restoration;
- repair/reinstall;
- non-purge uninstall/reinstall with state and update-trust preservation;
- browser-authenticated access;
- final diagnostics/evidence capture.

## Scope freeze
No new end-user features are planned for rc.1. The following contracts are frozen unless an acceptance-blocking defect requires a narrowly scoped fix:
- navigation: Обзор / Маркет / RBAC / Система;
- local authentication and admin/viewer authorization;
- state schema `1`;
- operations schema `1`;
- audit correlation and secret-safe diagnostics export;
- loopback-only secure runtime default;
- installer/repair/reinstall/non-purge uninstall lifecycle;
- signed manifest schema `1`;
- Ed25519 verification, SHA-256/size binding and platform/state compatibility;
- immutable release directories, atomic `current`/`previous`, rollback;
- secure product cookies and CSRF/origin enforcement.

## rc.1 deliverables
1. Exact release metadata for version `1.0.0-rc.1` and source commit.
2. Static linux/amd64 and linux/arm64 binaries with checksums.
3. Signed update package contract validation with no private key in artifacts.
4. Release manifest/changelog/evidence index.
5. Deterministic clean-install acceptance.
6. Upgrade acceptance from the accepted beta.1 real-host state.
7. Restart/reboot acceptance and service enablement verification.
8. Auth/RBAC/Operations/Audit/Diagnostics regression acceptance.
9. Signed update failure/rollback regression acceptance.
10. Repair/reinstall and preserve-state uninstall/reinstall acceptance.
11. Negative security checks: origin/CSRF, viewer privilege denial, malformed state/schema, tampered update package.
12. Secret-leak scan of release artifacts and diagnostics evidence.
13. Production-candidate readiness report with all blocking issues at zero.

## Release gates
rc.1 is promotable only if all of the following are true:
- `gofmt`, `go test ./...`, `go vet ./...` pass;
- shell and embedded Web JavaScript syntax checks pass;
- linux/amd64 and linux/arm64 static builds and checksums pass;
- GitHub branch integrity is verified;
- CI evidence is read-only and does not self-modify `main`;
- clean install and beta.1 -> rc.1 upgrade pass on a real systemd host;
- health/readiness/version are correct after restart and reboot;
- state, users, audit and operations survive supported lifecycle operations;
- signed update verification remains fail-closed;
- broken signed candidate rolls back and the known-good service can restart immediately;
- diagnostics bundle remains whitelist-only and secret-free;
- no blocker/critical release debt remains open.

## Explicitly deferred beyond 1.0.0
- Domain/AD and network infrastructure services;
- advanced Market/module lifecycle;
- remote automatic update discovery/download;
- Web-triggered privileged self-update;
- production HSM/signing-key management;
- support agent and commercial licensing;
- Android/mobile client.

## Main branch governance
Planning and candidate work remain isolated from `main`. No PR or merge is created by this plan. Promotion to `main` requires explicit acceptance after rc.1 evidence is complete.

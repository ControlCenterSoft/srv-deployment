# Control Center — руководство пользователя и администратора

> Статус: каноническое руководство новой линии разработки. Документ развивается вместе с продуктом. На момент начала новой ветки планируется релиз **2.2.0**; функции, еще не подтвержденные реализацией, отмечены как планируемые.

## 1. Обзор продукта

Control Center — единая веб-панель для установки, настройки и администрирования серверных компонентов. Новая линия разрабатывается с нуля и не предполагает, что поведение старых версий автоматически сохраняется.

Базовая навигация новой оболочки:

- **Обзор** — состояние узла и сводная информация;
- **Маркет** — каталог и жизненный цикл устанавливаемых компонентов;
- **RBAC** — управление субъектами, ролями и разрешениями;
- **Система** — системные параметры, обслуживание и диагностика.

## 2. Роли и доступ

Целевая модель доступа — RBAC (role-based access control). Права должны назначаться через роли, а не через разрозненные проверки имени пользователя.

Точная схема аутентификации новой линии будет зафиксирована после реализации соответствующего этапа. Старые утверждения о конкретном первом логине, локальном пароле или обязательной PAM/NSS-схеме не считаются действующими без подтверждения текущим кодом/релизом.

## 3. Установка

**Планируется для 2.2.0.** Первый этап новой разработки — установщик веб-интерфейса с сохранением утвержденного визуального направления.

До появления установочного артефакта в текущей ветке это руководство не публикует команды установки, которые нельзя проверить по фактическому пакету.

## 4. Первый вход

Процедура первого входа будет описана после фиксации механизма аутентификации и bootstrap-администратора. Документация не должна содержать универсальные заводские учетные данные, если они не подтверждены текущим релизом.

## 5. Интерфейс и модули

### Обзор

Предназначен для общего состояния системы и ключевых показателей. Детальный состав виджетов будет документироваться по факту реализации.

### Маркет

Новое название раздела, ранее называвшегося «Сервисы». Предназначен для установки, удаления и управления серверными компонентами.

### RBAC

Новое название раздела, ранее называвшегося «Пользователи». Предназначен для управления пользователями/субъектами, ролями и разрешениями.

### Система

Предназначен для системной конфигурации, обслуживания, обновлений и диагностических функций.

## 6. Системное администрирование

Раздел будет включать проверенные процедуры управления службами, журналами, сетью, хранилищем и системными параметрами. Команды должны соответствовать фактической архитектуре текущего релиза.

## 7. Обновления

Новая ветка должна различать версию приложения, release metadata и состояние установленной системы. Процедура обновления будет документироваться после реализации механизма доставки 2.2.x.

Замороженные файлы уже выпущенного релиза не редактируются задним числом. Исправление выпускается новой версией или отдельным документационным уточнением, не меняющим release payload.

## 8. Резервное копирование и восстановление

Планируемый раздел. Для каждого компонента будут определены: данные для резервирования, конфигурация, секреты (без публикации их значений), порядок восстановления и проверка результата.

## 9. Samba и домен

Планируемый раздел. Будет описывать только архитектуру и процедуры, реально реализованные в новой линии: доменные роли, интеграцию идентификации, DNS, членство клиентов и административные операции.

## 10. Общие ресурсы

Планируемый раздел для файловых ресурсов, ACL, групп доступа, пользовательских и общих каталогов.

## 11. Minecraft

Планируемый раздел для установки компонента через Маркет, жизненного цикла сервера, конфигурации, обновлений, миров, резервного копирования и диагностики.

## 12. Диагностика и устранение неисправностей

Для каждой функции будут приводиться безопасные проверки: состояние служб, журналы, сетевые проверки, состояние зависимостей и признаки корректной работы. Исторические incident-документы могут использоваться как справочный материал, но должны быть явно помечены как относящиеся к прежней версии.

## 13. Безопасность

Основные принципы документации и реализации:

- минимально необходимые права;
- централизованный RBAC;
- отсутствие секретов в репозитории и руководствах;
- явное разделение аутентификации и авторизации;
- проверяемые процедуры обновления и восстановления;
- неизменяемость опубликованных release payloads.

## 14. Релизы и версии

Версия описывает конкретное состояние продукта. ROADMAP описывает план, а RELEASE-HISTORY — фактически выпущенные версии. Эти источники не должны противоречить друг другу.

Новая разработка планируется с версии **2.2.0**. Старые материалы могут быть сохранены в архиве для истории, но не являются спецификацией текущего продукта.

## 15. Статус разделов

По мере реализации 2.2.x этот документ будет последовательно дополняться проверенными процедурами установки, первого входа, RBAC, системного администрирования, обновления, backup/restore, Samba/домена, shares, Minecraft и troubleshooting.

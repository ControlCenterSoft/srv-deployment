## Slice

Adds one read-only follow-up to the accepted top-level block-device inventory:

- `GET /api/v1/storage/partitions` under existing `system.read` authorization;
- deterministic Linux sysfs partition inventory with parent device, kernel partition number, start offset and size;
- bounded degradation warnings without raw host errors or host paths;
- existing device inventory now truthfully advertises that bounded partition inventory is supported;
- success/failure reads use dedicated `storage.partitions.read` audit action.

## Safety boundary

This slice remains non-mutating and unprivileged:

- reads only `/sys/block` metadata;
- does not open block devices;
- does not expose serial/WWN, filesystem UUID/label, mount path, backing file, vendor/model or user content;
- does not call the privileged worker or execute shell commands;
- filesystems and mounts remain unsupported;
- preview, preflight and apply remain unsupported with `storage_mutation_not_implemented`.

Any future storage mutation remains gated by `preview -> preflight -> validation -> apply -> verify -> rollback/recovery` and is explicitly outside this slice.

## Author-side validation

On Go `1.23.2`, the isolated `internal/storage` fixture suite for the new partition inventory passes after `gofmt`, including deterministic ordering, ordinary non-partition sysfs entries, malformed metadata, overflow handling and unavailable inventory root.

Repository-wide Fast CI plus independent Contract & Regression QA and Security Review remain authoritative before integration. Merge/release/deploy remain owned by `CC Integrator, Release & Docs`.

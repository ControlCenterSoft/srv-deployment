# Core A — Operations detail contract evidence

Date: 2026-08-22

## Scope

This bounded Core A slice adds an exact read-only operation lookup to the existing Operations foundation:

- `GET /api/v1/operations/{id}`;
- exact in-memory lookup in the existing durable operation store;
- no operation mutation, state-schema change, release metadata change, privileged execution, Admin Web work, Core B work or iOS work.

The implementation started from exact canonical `1.1.x` base `430e1a779ae6e18c09618d4392915bd1489ea423` after the previous Core A Fleet feature had been integrated. Open PR file sets were inspected before editing. This slice does not touch the Fleet files held by Integrator gate PR #199, Admin Web files in #141/#138, DNS files in #161, AI files in #150/#164, or release-gate workflow files in #205/#209.

## API and permission contract

Successful response is additive and versioned with `contract_version=1`. It returns:

- the exact existing `operations.Record` object;
- `permissions.read=operations.read` metadata;
- read-model health metadata showing the operation store is available;
- `observed_at` timestamp.

The route uses the existing `operations.read` permission and therefore preserves current RBAC semantics: administrator access is allowed; viewer access is denied.

## Validation and stable errors

Operation IDs accepted by the HTTP lookup are bounded to 1..128 characters and the backward-compatible character set `[A-Za-z0-9._:-]` with an alphanumeric first character.

Stable errors:

- unauthenticated: `401 authentication_required`;
- authenticated without `operations.read`: `403 permission_denied`;
- malformed operation identifier: `400 invalid_operation_id`;
- well-formed unknown operation identifier: `404 operation_not_found`.

No request can mutate operation records through this endpoint.

## Audit semantics

Authenticated reads emit `operations.detail.read` audit events:

- successful lookup → `result=success`;
- malformed ID → `result=failed`, `error_code=invalid_operation_id`;
- missing record → `result=failed`, `error_code=operation_not_found`;
- authenticated permission denial → `result=denied`, `error_code=permission_denied`.

The target is the requested operation identifier. No credentials, request bodies or sensitive operation payloads are copied into the audit event.

## Health semantics

A successful lookup includes `health.status=healthy` and `health.operation_store=true`. Platform readiness continues to own process-level operation-store readiness; this endpoint does not invent an independent health source or weaken `/api/v1/readiness`.

## Deterministic acceptance coverage

Focused tests cover:

- exact store lookup and missing/empty IDs without mutation;
- successful administrator lookup and contract metadata;
- anonymous rejection;
- viewer RBAC rejection;
- malformed ID rejection;
- missing operation rejection;
- success/failure/denial audit evidence.

Repository CI is authoritative for compilation, Go formatting/vetting and regression execution on the final PR head. Any head change invalidates prior exact-SHA evidence.

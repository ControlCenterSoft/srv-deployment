# Control Center 1.1.x — Admin Web audit coverage

## Development lane synchronization

This bounded slice is now targeted at the isolated `1.2.x` development line. The functional delta remains the same read-only Admin Web coverage; release-only `1.1.x` acceptance/staging is not part of this PR. Prior exact-base CI evidence is superseded by fresh `1.2.x` CI on this synchronized head.

## Core capability

The stable Core A audit contract is `GET /api/v1/audit` protected by the existing `audit.read` permission. Existing server tests prove that an authenticated admin can read audit events and a viewer receives `403 Forbidden`; audit entries are server-side records with operation IDs, actor/role, action, target, result and optional error code.

## Admin Web workflow

This Experience slice adds a read-only **Аудит** workflow without changing Core semantics:

- the navigation entry is available only to an authenticated admin;
- the page loads the latest 50 events from the existing API;
- data is rendered only with DOM/text nodes, never HTML interpolation;
- the view exposes timestamp, action/result, actor/role, target, operation ID and error code for traceability;
- remote IP is intentionally not rendered by default;
- loading, empty, refresh and failure states are user-visible;
- navigation hides competing workflow panels and preserves the existing Network/RBAC/System behavior.

## Acceptance evidence

Automated coverage:

- `TestAdminWebAuditWorkflowContract` pins the API path, admin-only navigation, trace fields, live-region semantics and safe text rendering;
- `TestAdminWebAuditModuleSyntax` runs `node --check` on the embedded `audit.js` module;
- `TestAdminWebAuditPageIsolationContract` verifies that switching to Audit hides other workflow panels;
- existing `TestOperationAuditAndDiagnosticsEndpoints` and `TestViewerCannotReadAuditOrOperations` remain the authoritative backend permission/API tests.

This change is additive and does not modify authentication, RBAC, audit storage, API response semantics, privileged execution, release identity or server state.

# Core A acceptance evidence — Fleet agent auto-heartbeat

Status: candidate, pending exact-head Fast CI completion.

## User-facing vertical slice

После подготовки enrollment администратор получает стабильный agent setup contract и может установить на управляемый Linux-сервер минимальный Fleet Agent. Агент выполняет одноразовый enrollment, сохраняет отдельный bearer credential локально и затем автоматически отправляет heartbeat/inventory каждую минуту. После этого сервер сам появляется как `healthy` в Fleet без ручных API-вызовов.

Основной Admin Web не дублируется: backend отдаёт web-consumable metadata, пути bootstrap и permission model для потока Experience.

## Web/API contract для Experience Admin Web

`GET /api/v1/fleet/capabilities` — authenticated, доступен `admin` и `viewer`:

- `contract_version=1`;
- роли для Fleet read/create/enrollment prepare;
- agent auth model: one-time enrollment token → отдельный bearer credential;
- Fleet Agent version, install/source paths, heartbeat interval и runtime hardening metadata;
- health thresholds/states.

`POST /api/v1/fleet/nodes/{id}/enrollment` сохраняет существующие поля и аддитивно возвращает `agent_setup` с тем же стабильным setup contract.

Публичные static bootstrap assets без секретов:

- `GET /api/v1/fleet/agent/install.sh`;
- `GET /api/v1/fleet/agent/agent.py`.

Оба ответа содержат `X-Control-Center-Fleet-Agent-Version` и SHA-256 source identity; installer содержит exact digest агента и проверяет его перед установкой.

## Node-side security model

- Fleet Agent не содержит shell/command execution API и не имеет privileged action contract.
- Enrollment token читается только из интерактивного TTY либо root-owned файла 0400/0600; token не сохраняется после bootstrap.
- После enrollment plaintext agent credential хранится только на managed node в mode 0600; сервер хранит только SHA-256 digest по существующему Fleet contract.
- Постоянный systemd service запускается как dedicated `control-center-fleet` без root, capabilities и `NoNewPrivileges=true`.
- Agent принимает production Control Center URL только по HTTPS; HTTP разрешён только для loopback acceptance/testing.
- HTTP redirects отключены как для agent API calls, так и для загрузки agent source installer-ом.
- Heartbeat отправляет только bounded inventory: agent version, hostname, OS name/version, architecture.
- Agent bearer не наследует browser session/RBAC права и применяется только к heartbeat endpoint.

## Failure / repair behavior

- Невалидный/истёкший enrollment token остаётся fail-closed на сервере и не создаёт локальный credential.
- Network/TLS/HTTP/JSON failures завершают oneshot heartbeat ошибкой без вывода credential/token; systemd timer повторяет следующий bounded heartbeat.
- Повторный installer без `FLEET_REENROLL=1` сохраняет действующий agent credential.
- Явный re-enrollment использует новый one-time token и заменяет local credential только после успешного server enrollment; если локальная запись нового credential после успешного server-side enrollment не удалась, repair path — новый enrollment token и повторный явный re-enrollment.
- Digest mismatch загруженного agent source прерывает installation до записи executable.

## Automated acceptance

1. Existing Fleet RBAC/auth/CSRF/credential tests remain green.
2. Capability metadata доступна admin и viewer и содержит стабильную permission/auth модель.
3. Enrollment response аддитивно публикует `agent_setup`.
4. Static agent/installer доступны без browser session и не содержат enrollment credential.
5. Served agent SHA-256 совпадает с embedded bytes и exact digest, встроенным в installer.
6. Installer проходит `bash -n`; Python agent проходит `--self-test` в CI.
7. Negative acceptance запрещает remote plain HTTP до чтения credential; installer отдельно валидирует URL как origin и root ownership token file.
8. Real agent integration test запускает embedded Python client против `httptest` Control Center: one-time enrollment → отдельный credential → authenticated heartbeat → `healthy` Fleet inventory.
9. Integration test подтверждает mode 0600 local credential и отсутствие token/credential в Fleet API output.
10. Fast CI дополнительно выполняет gofmt/vet/unit+contract tests, linux build, policy/secrets и development release gate.

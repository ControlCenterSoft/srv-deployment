## UX, accessibility, security and performance

- New Core A capability is consumed rather than reimplemented: installer metadata, transport requirements and heartbeat cadence come from `/api/v1/fleet/capabilities` / `agent_setup`.
- Fleet inventory and capability metadata are loaded concurrently with `Promise.all` to avoid a serial request waterfall.
- Fleet installer link is required to remain same-origin. Remote plain HTTP is not offered; HTTP is accepted only for loopback testing, matching the Core contract.
- One-time enrollment token is shown once, separately from the install command; it is not persisted or embedded in URL/argv.
- RBAC navigation is hidden for non-admin sessions; mutations remain server-authoritative with existing CSRF, self-block protection and session revocation.
- API-controlled usernames/roles/status are rendered through DOM text nodes; the previous RBAC dynamic `innerHTML` interpolation sink is removed.
- Mutation errors use alert regions, form fields have explicit labels, and interactive controls expose visible keyboard focus.
- Network navigation explicitly hides the RBAC mutation form so workflows do not leak across pages.

# Control Center 1.1.x — DNS resolver preview evidence

## Scope

Core B infrastructure vertical slice extending the accepted DNS resolver actual-state inventory with an admin-only, non-applying preview contract.

## Contract

- `GET /api/v1/dns/resolver` continues to expose authoritative actual state and now advertises `preview_supported=true`, while `apply_supported=false` remains explicit.
- `POST /api/v1/dns/resolver/preview` accepts desired nameservers and search domains.
- The response carries normalized `desired`, authoritative `actual`, explicit `rollback`, a no-op marker and preconditions required by a future recovery-aware executor.
- Resolver options are preserved from actual state and are not user-editable in this slice.
- No privileged mutation or resolver file write is implemented.

## Security and validation

- Authentication is required.
- Only the `admin` role may preview resolver changes.
- POST requests require the existing CSRF/origin mutation boundary.
- Nameservers must be valid unicast IP addresses; unspecified, multicast and zoned addresses are rejected.
- Search domains are normalized and bounded; control characters, separators, invalid labels and oversized inputs are rejected.
- Validation failures and successful previews are audit events under `dns.resolver.preview`.
- No secret, token, PII or provider credential is handled by this capability.

## Recovery model

The planner explicitly records the current resolver state as rollback state and requires these future-executor preconditions:

1. resolver inventory remains available;
2. resolver source kind is revalidated before apply;
3. current resolver state is backed up;
4. DNS resolution is verified before commit;
5. verification failure triggers rollback.

`apply_supported=false` intentionally blocks any privileged mutation until the dedicated executor implements and proves these recovery guarantees.

## Acceptance

Unit coverage verifies normalization, desired/actual/rollback projection, option preservation, no-op detection and rejection of unsafe input. HTTP coverage verifies anonymous denial, admin + CSRF enforcement, viewer denial, machine-readable validation errors and the complete no-op preview envelope.

The branch is file-isolated from all open non-Core-B PRs observed before development. Merge remains owned by `CC Integrator, Release & Docs` after required CI, independent QA and Security evidence on the exact final head SHA.

# Control Center 1.1.x — DNS resolver preflight evidence

## Scope

Core B infrastructure vertical slice extending the accepted DNS resolver inventory and preview contracts with a non-mutating preflight API. The slice does not write resolver files, restart services or enable apply.

## Contract

- `GET /api/v1/dns/resolver` advertises `preflight_supported=true` while `apply_supported=false` remains explicit.
- `POST /api/v1/dns/resolver/preview` now returns a deterministic `source_fingerprint` bound to authoritative resolver source identity and effective resolver state.
- `POST /api/v1/dns/resolver/preflight` is admin-only, requires the existing CSRF/origin mutation boundary, and requires `expected_source_fingerprint` copied from the preview result.
- Desired state is revalidated through the accepted resolver planner.
- Preflight re-inventories resolver state and compares the current fingerprint with the preview fingerprint; a changed resolver source/state returns the explicit `resolver_source_unchanged` blocker rather than silently continuing with stale evidence.
- Preflight returns Desired, authoritative Actual, explicit Rollback, machine-readable checks/blockers and the required recovery-aware executor steps.

## Current non-mutating checks

1. resolver inventory is available and contains nameservers;
2. resolver source kind is one of the explicitly understood `resolv_conf` or `systemd_resolved` models;
3. a current source/state fingerprint can be produced;
4. current resolver source/state matches the exact fingerprint from preview;
5. desired state has passed the accepted resolver validation rules;
6. rollback state contains the authoritative current nameservers.

Missing or malformed expected fingerprints are rejected as validation errors. Unsupported source kinds and stale-but-well-formed preview fingerprints are returned as explicit preflight blockers rather than guessed or mutated.

## Recovery boundary

Apply remains disabled until a dedicated privileged executor proves these ordered steps:

1. backup current resolver state;
2. apply desired resolver state through the source-appropriate mechanism;
3. verify DNS resolution before commit;
4. rollback automatically on verification failure.

A future apply endpoint must also require the exact successful preflight fingerprint and re-inventory immediately before privileged mutation. No arbitrary shell surface, resolver file write, service restart or privileged helper expansion is introduced by this slice.

## Security / audit

- anonymous requests are rejected by authentication;
- viewer requests are denied and audited as `dns.resolver.preflight` / `permission_denied`;
- admin POST requires CSRF/origin validation;
- validation errors use bounded input rules, including fixed-form `sha256:` fingerprint validation;
- preflight success/failure is audited;
- no secret, token or PII is processed or returned.

## Acceptance coverage

- deterministic fingerprint generation and authoritative-state change detection;
- preview → preflight fingerprint handoff;
- missing/malformed expected fingerprint rejection;
- stale preview fingerprint detection via `resolver_source_unchanged`;
- supported/unsupported resolver source handling;
- desired/actual/rollback preservation and executor-step contract;
- anonymous/admin/viewer and CSRF HTTP boundaries;
- inventory capability advertisement;
- no-op preflight response with exact preview fingerprint and recovery steps;
- audit evidence for denied viewer preflight.

The branch is isolated from active Experience, Visual UI, Fleet and AI Gateway PR file sets. Merge remains owned by `CC Integrator, Release & Docs` after CI and independent exact-SHA QA/Security evidence.

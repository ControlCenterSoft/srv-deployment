## Scope

This slice adds a bounded read-only Actual-state inventory for top-level Linux block devices. It does not add partition, filesystem, mount, format, resize, RAID/LVM, backup, restore, or any other storage mutation semantics.

API contract:

- `GET /api/v1/storage/devices`
- existing Core A permission: `system.read`
- audit action: `storage.devices.read`
- stable failure code for an unavailable inventory root: `storage_inventory_unavailable`
- per-device hot-unplug or malformed required sysfs metadata degrades to bounded `device_disappeared` / `device_metadata_unavailable` warnings rather than leaking raw host errors
- `management.inventory_supported=true`
- `management.scope=top_level_block_devices`
- partition/filesystem/mount discovery is explicitly not advertised by this slice
- preview/preflight/apply are explicitly `false` with reason `storage_mutation_not_implemented`

## Safety and privacy boundary

The unprivileged core reads only bounded block metadata from `/sys/block`: kernel device name, capacity, read-only/removable flags and optional logical/physical block sizes.

The response deliberately excludes serial numbers, WWNs, vendor/model strings, filesystem labels, mount paths, device-mapper UUIDs/names, loop backing files and user content. No privileged worker call, shell execution, config write, device open, mount, unmount or storage mutation is introduced.

Any future mutation remains gated by the Core B invariant: preview -> preflight -> validation -> apply -> verify -> rollback/recovery. This slice intentionally stops before that boundary.

Kernel references used for the read-only model:

- Linux block sysfs ABI: https://docs.kernel.org/admin-guide/abi-stable.html
- Linux queue sysfs documentation (logical/physical block size): https://docs.kernel.org/block/queue-sysfs.html
- Linux block statistics sector convention: https://docs.kernel.org/block/stat.html

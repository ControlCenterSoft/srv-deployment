## Defect discovered by real-host acceptance v4

Candidate `dab8d8db18a80309fdad3f7dfb6597af74b861db` built successfully on the real host but produced a different SHA-256 because `scripts/build-release.sh` used `git show --format=%cI`. Git preserves the commit timezone in `%cI`, so the real host embedded `2026-08-20T16:19:56+03:00` while the prior local reference embedded the equivalent instant `2026-08-20T13:19:56Z`.

The failure occurred at `build-exact-candidate` before rc.1 installation. Diagnostics evidence confirmed the host remained on accepted beta.1, state/secrets hashes were unchanged, service/readiness/proxy were healthy, and the ephemeral private test key was removed.

## Fix

Commit `2b104ffa69d5f11b1a4de24fe92be95d89422acd` changes only `scripts/build-release.sh` to:
- read the immutable Git commit epoch using `%ct`;
- canonicalize the epoch with `date -u` to `YYYY-MM-DDTHH:MM:SSZ`;
- fail closed unless the canonical timestamp has the UTC `Z` form.

A synthetic Git commit created with `2026-08-20T16:19:56+03:00` canonicalized to `2026-08-20T13:19:56Z` — PASS.

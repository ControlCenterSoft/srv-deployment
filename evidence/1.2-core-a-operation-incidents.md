## User-facing platform contract

`GET /api/v1/operations/incidents` exposes a bounded newest-first feed of abnormal terminal operations so an operator does not need to scan successful/running history to identify failures.

The additive response keeps the existing operation record schema and declares:

- `contract_version=1`;
- `incidents`: only `failed` and `interrupted` operation records;
- `count`, `bounded=true`, and the effective `limit`;
- `statuses=["failed","interrupted"]`;
- `permissions.read=operations.read`;
- operation-store and audit-log health metadata;
- `observed_at`.

The default limit is 50. Explicit limits are strict and bounded to 1..100. Malformed, zero, negative, or over-limit values fail with stable HTTP 400 `invalid_limit`; they are not silently rewritten.

## Security, RBAC and audit semantics

- Authentication remains server-side and the existing `operations.read` permission remains authoritative.
- Viewer/unauthorized access cannot read incident records; authenticated permission denial is audited as `operations.incidents.read` / `permission_denied`.
- Successful incident reads are audited as `operations.incidents.read`.
- Invalid-limit requests from an authenticated authorized caller are audited with `invalid_limit`.
- The projection reuses the existing safe operation schema and contains no request body, password, session cookie/token, CSRF token, or other credential material.
- No mutation, privileged execution, Desired/Actual state change, Fleet mutation, Core B behavior, Admin Web behavior, release identity, deployment, or iOS behavior is introduced.

## Failure and health behavior

- If the operation store is unavailable, the endpoint fails closed with HTTP 503 `operation_store_unavailable`.
- Missing audit wiring does not fabricate audit evidence; the read remains available but reports degraded audit health.
- Existing restart recovery remains authoritative: an unfinished `running` operation is converted by the store to `interrupted` with `process_restarted`, and therefore appears in the incident feed.

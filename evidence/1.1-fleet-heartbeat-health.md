# Core A acceptance evidence — Fleet heartbeat health inventory

Status: candidate, pending exact-head Fast CI completion.

## User-facing vertical slice

An administrator can enroll a managed server and Control Center then exposes its current connectivity freshness, last contact, agent version and basic OS identity in the Fleet inventory. A viewer can inspect Fleet state but cannot create nodes or issue enrollment credentials.

## Security and trust contract

- Enrollment remains a short-lived, one-time credential.
- Successful enrollment generates a separate 256-bit random agent bearer credential.
- Only the SHA-256 digest of the agent credential is persisted; the plaintext credential is returned once at enrollment.
- Fleet list and enrollment responses never expose enrollment-token or agent-credential digests.
- Heartbeat requires the agent bearer credential and has no browser session/RBAC privileges.
- Invalid heartbeat credentials fail closed and are audited.
- Successful heartbeat identity updates are audited with the Fleet node as target.

## Health semantics

- `healthy`: last accepted heartbeat is at most 2 minutes old.
- `stale`: heartbeat is older than 2 minutes and at most 15 minutes old.
- `offline`: heartbeat is older than 15 minutes.
- `unknown`: node is not enrolled or has no accepted heartbeat timestamp.

Health is derived from persisted `last_seen_at`; `unknown/stale` are explicit states rather than aliases for healthy.

## Inventory contract

Heartbeat can update these bounded fields:

- agent version;
- hostname;
- OS name and OS version;
- architecture;
- last seen timestamp.

`GET /api/v1/fleet/nodes` preserves the existing flat node shape and adds `health` plus `last_seen_seconds_ago`; its summary adds healthy/stale/offline counts.

## Compatibility / migration

Nodes enrolled before this slice have no persisted agent credential and therefore cannot authenticate heartbeat. They remain visible and resolve to existing/unknown freshness state. An administrator can issue a new enrollment token and re-enroll the node to provision the agent credential; no destructive state migration is performed automatically.

## Automated acceptance

The branch tests cover:

1. node persistence and validation;
2. one-time enrollment token rejection on replay;
3. one-time agent credential issuance and non-disclosure of its digest;
4. heartbeat rejection without/with wrong credential;
5. authenticated heartbeat inventory update and persistence;
6. healthy Fleet summary and inventory projection;
7. admin positive Fleet mutation authorization;
8. viewer positive Fleet read and negative Fleet mutation authorization;
9. CSRF enforcement on browser/admin Fleet mutations;
10. existing repository policy, secret scan, build, vet and unit/contract tests through the 1.1.x Fast CI gate.

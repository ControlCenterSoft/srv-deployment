## User-visible workflow

On **Система** for an admin:

1. recent operations retain the existing bounded `GET /api/v1/operations?limit=10` source;
2. each operation exposes a keyboard-accessible detail control using the Core operation ID;
3. selection loads `GET /api/v1/operations/{id}` with the ID encoded as one path segment;
4. the detail panel shows authoritative kind/status/actor/role/target/timestamps/error code;
5. the panel shows Core-provided health metadata and bounded correlated audit evidence from the same detail response;
6. audit role denial, audit-component degradation and zero correlated events are represented explicitly rather than reconstructed client-side;
7. stale detail responses are ignored when a newer operation selection wins.

The Web layer does not infer operation history, does not query the global audit endpoint for correlation, and does not consume the unmerged `/api/v1/operations/incidents` contract.

## Loading / error / empty / accessibility

- explicit polite live loading/status text for recent operations;
- explicit empty state when no operations exist;
- localized recent-operation failure instead of blanking diagnostics/network data;
- selected detail control is disabled while its request is active;
- detail loading state uses `role=status` + `aria-live=polite`;
- detail failures use `role=alert`;
- detail controls carry operation-specific accessible names;
- API values are rendered through text nodes/textContent only.

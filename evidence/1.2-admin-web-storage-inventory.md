## User-visible workflow

The existing **Система** page now loads a dedicated storage inventory projection from the accepted Core B contract.

The Web layer renders:

- top-level block-device identity using the Core-provided `/dev/<name>` path;
- capacity, read-only/read-write state and fixed/removable state;
- optional logical and physical block sizes where Core provides them;
- explicit empty inventory state;
- bounded per-device warning codes returned by Core;
- server-authoritative capability metadata for inventory, partitions, filesystems, mounts, preview, preflight and apply support;
- the Core-provided management limitation reason when present.

Storage loading is isolated from the existing diagnostics/network/operations loaders. A storage failure therefore does not blank the rest of the System page.

## Loading, error, accessibility and stale-response behavior

- explicit `Загрузка инвентаря накопителей…` live status;
- explicit `Блочные устройства не обнаружены.` empty state;
- explicit alert state for API failure;
- bounded warning list for degraded per-device inventory;
- navigation-generation guard suppresses a late storage response after the user leaves/re-enters the System page;
- API-derived values are assigned through `textContent`; no new HTML interpolation path is introduced;
- existing compact-list visual primitives are reused; no design-system/CSS change is included.

## Core authority and safety boundary

This slice consumes the existing read-only Core contract only. It does not:

- add a storage POST/PUT/PATCH/DELETE request;
- invent partition/filesystem/mount discovery;
- expose preview/preflight/apply controls when Core reports them unsupported;
- duplicate sysfs parsing, capacity calculation, authorization, audit or warning classification in JavaScript;
- request or render serial/WWN, filesystem labels, mount paths, backing-file metadata or user content;
- touch privileged worker, storage mutation, release identity, Android or iOS behavior.

Future storage mutation remains a Core B concern and must preserve the existing preview -> preflight -> validation -> apply -> verify -> rollback/recovery invariant before Experience exposes any write workflow.
